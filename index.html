Уровень 1 — базовая выборка

SELECT / FROM

SELECT — «выбери»

Кто не играл в Денди/Сегу? В данном случае употребляется в повелительном наклонении — приказ СУБД выбрать что-то.

FROM — «из»

Да-да, как вы уже догадались — «ИЗ» чего-то (или отобрать у кого-то; наше дело маленькое — сказать, а у кого СУБД отбирать будет... проблемы индейцев шерифов не волнуют).

Нюанс

Порядок «сначала SELECT , потом FROM » — обман зрения. СУБД сначала читает FROM , потом WHERE , и только в конце вычисляет SELECT . Об этом — в разделе «Порядок выполнения запроса».

Рабочий пример: SELECT / FROM на практике 

SELECT /* выбираем столбцы результата */ name, salary
FROM /* указываем таблицу-источник */ Employee;

СУБД берёт строки из Employee и возвращает только столбцы name и salary.

1. Данные ДО запроса

Employee
id name salary
1 Анна 90000
2 Борис 65000

2. Запрос 

SELECT /* выбираем столбцы результата */ name, salary
FROM /* указываем таблицу-источник */ Employee;

3. Что получится

Данные до запроса: Employee содержит (name, salary) : Анна — 90 000; Борис — 65 000.
Результат: две строки: Анна | 90000 и Борис | 65000 . Столбцы id и другие поля не выводятся.

Как выглядит результат

name salary
Анна 90000
Борис 65000

Выбраны только указанные столбцы; id не выводится.

Сложный вариант 1: Выбрать несколько столбцов и вычислить доплату

Сначала отбираются сотрудники с зарплатой от 80 000, затем для них рассчитывается бонус, после чего строки сортируются по зарплате по убыванию. 

SELECT /* выводим нужные поля и вычисляем итог */
    e.name,
    e.salary,
    e.salary * 0.10 AS bonus /* бонус равен 10% зарплаты */
FROM /* источник данных */ Employee AS e
WHERE /* берём только сотрудников с зарплатой от 80000 */ e.salary >= 80000
ORDER BY /* сначала самые высокие зарплаты */ e.salary DESC;

На что обратить внимание: Комментарии внутри запроса объясняют назначение частей. Попробуй убрать комментарии и пересказать логику своими словами.

AS

AS — «в качестве»

Левый операнд AS — это правый операнд. Можно перевести как «обзови всё, что слева, фразой справа».

Нюанс

У AS есть два лица. Первое — псевдоним столбца: salary AS зарплата . Второе — псевдоним таблицы: FROM Employee AS e . Это разные вещи, но логика одна: «с этого момента называй вот это вот так».

Рабочий пример: Псевдонимы через AS 

SELECT /* выбираем столбцы результата */ salary AS зарплата
FROM /* указываем таблицу-источник */ Employee AS e;

salary показывается под именем «зарплата», а таблица Employee получает короткое имя e.

Показать исходные таблицы и результат

1. Данные ДО запроса

Employee
id name salary
1 Анна 90000
2 Борис 65000

2. Запрос 

SELECT /* выбираем столбцы результата */ salary AS зарплата
FROM /* указываем таблицу-источник */ Employee AS e;

3. Что получится

Данные: в таблице есть salary = 90000 .
Результат: столбец будет называться зарплата и содержать 90000 . e — короткое имя таблицы, например e.salary .

Как выглядит результат

зарплата
90000
65000

AS меняет название столбца в выдаче, но не исходное имя поля в таблице.

Сложный вариант 2: Использовать несколько псевдонимов

Псевдонимы меняют названия столбцов только в результате запроса. Они не переименовывают столбцы в самой таблице. 

SELECT /* задаём понятные имена результирующим столбцам */
    e.name AS employee_name,
    e.salary AS monthly_salary,
    e.salary * 12 AS yearly_salary /* условный годовой доход без премий */
FROM /* задаём таблицу и короткий псевдоним */ Employee AS e;

На что обратить внимание: Комментарии внутри запроса объясняют назначение частей. Попробуй убрать комментарии и пересказать логику своими словами.

WHERE

WHERE — «где»

«Где-где...? — В Караганде... которая находится в РФ» — или «в гнезде, в котором именно 2 яйца, а не 3-5-6», кому как нравится.

Нюанс

WHERE работает со строками и ничего не знает про агрегаты. Попытка написать WHERE COUNT(*) > 5 закончится ошибкой — для этого есть HAVING .

Рабочий пример: Отбор строк через WHERE 

SELECT /* выбираем столбцы результата */ name, salary
FROM /* указываем таблицу-источник */ Employee
WHERE /* фильтруем отдельные строки */ salary >= 80000;

Останутся только сотрудники с зарплатой не ниже 80 000. Условие применяется к каждой строке.

Показать исходные таблицы и результат

1. Данные ДО запроса

Employee
name salary
Анна 90000
Борис 65000
Ирина 45000

2. Запрос 

SELECT /* выбираем столбцы результата */ name, salary
FROM /* указываем таблицу-источник */ Employee
WHERE /* фильтруем отдельные строки */ salary >= 80000;

3. Что получится

Данные: Анна — 90 000; Борис — 65 000; Ирина — 45 000.
Результат: Анна и Борис попадут в выдачу, Ирина — нет, потому что её зарплата меньше 80 000.

Как выглядит результат

name salary
Анна 90000

Остальные строки отсеяны условием WHERE salary >= 80000.

Сложный вариант 3: Сочетать условия и исключить отдельный статус

Скобки гарантируют, что сначала проверяется одно из двух условий, а затем исключаются сотрудники со статусом dismissed. 

SELECT /* показываем сотрудников, подходящих под условия */ name, salary, status
FROM /* читаем таблицу сотрудников */ Employee
WHERE /* скобки задают порядок логических проверок */ (salary >= 90000 OR status = 'lead')
  AND status <> 'dismissed' /* исключаем уволенных */
ORDER BY salary DESC; /* сортируем по убыванию зарплаты */

На что обратить внимание: Комментарии внутри запроса объясняют назначение частей. Попробуй убрать комментарии и пересказать логику своими словами.

ORDER BY

ORDER — «порядок»

В каждом доме должен быть, а в голове и подавно (плохо, когда там каша-малаша)! ;)

ASC / DESC — «по возрастанию / по убыванию»

ASC — от меньшего к большему, DESC — от большего к меньшему. По умолчанию — ASC .

ASC можно писать только в ORDER BY и в CREATE INDEX . В GROUP BY и HAVING его быть не должно — оттуда и берётся ошибка syntax error at or near "ASC" .

Рабочий пример: Сортировка через ORDER BY 

SELECT /* выбираем столбцы результата */ name, salary
FROM /* указываем таблицу-источник */ Employee
ORDER BY /* сортируем результат */ salary DESC;

Сначала будут сотрудники с самой высокой зарплатой; DESC означает убывание.

Показать исходные таблицы и результат

1. Данные ДО запроса

Employee
name salary
Анна 90000
Борис 140000
Ирина 65000

2. Запрос 

SELECT /* выбираем столбцы результата */ name, salary
FROM /* указываем таблицу-источник */ Employee
ORDER BY /* сортируем результат */ salary DESC;

3. Что получится

Данные: Анна — 90 000; Борис — 140 000; Ирина — 65 000.
Результат: Борис → Анна → Ирина. DESC ставит большую зарплату выше.

Как выглядит результат

name salary
Борис 140000
Анна 90000
Ирина 65000

Строки отсортированы по salary от большего к меньшему.

Сложный вариант 4: Сортировать по нескольким критериям

СУБД сортирует сначала по номеру отдела. При одинаковом отделе более высокая зарплата идёт раньше; при равной зарплате имена упорядочиваются по алфавиту. 

SELECT /* выводим список сотрудников */ name, department_id, salary
FROM Employee /* источник данных */
ORDER BY /* сначала отделы, внутри отдела — зарплата */ department_id ASC, salary DESC, name ASC;

На что обратить внимание: Комментарии внутри запроса объясняют назначение частей. Попробуй убрать комментарии и пересказать логику своими словами.

LIMIT / OFFSET

LIMIT — «ограничь»

Сколько строк вернуть. LIMIT 10 — первые десять.

OFFSET — «смести»

Сколько строк пропустить. LIMIT 10 OFFSET 20 — пропустить двадцать, вернуть следующие десять. Классическая пагинация.

Нюанс

Без ORDER BY LIMIT бессмыслен: СУБД вернёт «первые попавшиеся» строки, и при повторном запуске они могут оказаться другими. Хотите стабильный результат — сначала отсортируйте.

Рабочий пример: Постраничный вывод 

SELECT /* выбираем столбцы результата */ id, name
FROM /* указываем таблицу-источник */ Employee
ORDER BY /* сортируем результат */ id
LIMIT /* ограничиваем число строк */ 10 OFFSET 20;

Сортируем по id, пропускаем первые 20 строк и выводим следующие 10.

LIMIT /* ограничиваем число строк */ 10 OFFSET 20;

Если после сортировки по id есть строки с id от 1 до 35, то OFFSET 20 пропустит id 1–20, а LIMIT 10 вернёт id 21–30.

Схематично показаны первые строки выдачи после пропуска 20 строк; LIMIT 10 вернёт всего 10 строк.

Сложный вариант 5: Реализовать пагинацию с устойчивой сортировкой

Такой запрос показывает третью страницу при размере страницы 10. Дополнительная сортировка по уникальному id делает порядок стабильнее. 

SELECT /* получаем одну страницу сотрудников */ id, name, salary
FROM Employee
ORDER BY salary DESC, id ASC /* id разрешает равенство зарплат */
LIMIT 10 OFFSET 20; /* 10 строк после пропуска первых 20 */

На что обратить внимание: Комментарии внутри запроса объясняют назначение частей. Попробуй убрать комментарии и пересказать логику своими словами.

DISTINCT

DISTINCT — «различный», «уникальный»

Убирает дубликаты из результата. SELECT DISTINCT city FROM Client вернёт список городов, где каждый город встречается один раз.

Нюанс

DISTINCT — это «покажи уникальные значения». GROUP BY — это «сгруппируй и посчитай». Первое — когда нужен список, второе — когда нужны агрегаты.

Рабочий пример: Уникальные значения 

SELECT /* выбираем столбцы результата */ DISTINCT city
FROM /* указываем таблицу-источник */ Client;

Каждый город попадёт в результат один раз, даже если в нём много клиентов.

FROM /* указываем таблицу-источник */ Client;

Данные: Москва, Казань, Москва, Омск.
Результат: Москва, Казань, Омск — каждый город только один раз.

Сложный вариант 6: Найти уникальные города и отсортировать их

DISTINCT применяется к сочетанию всех выбранных столбцов. Здесь каждый город появится один раз. 

SELECT DISTINCT /* убираем повторяющиеся значения */ city
FROM Client
WHERE city IS NOT NULL /* не включаем неизвестный город */
ORDER BY city ASC; /* упорядочиваем по алфавиту */

На что обратить внимание: Комментарии внутри запроса объясняют назначение частей. Попробуй убрать комментарии и пересказать логику своими словами.

Уровень 2 — фильтрация

AND / OR / NOT

AND — «и»

Оба условия должны быть истинны. Как в жизни: и то, и другое.

OR — «или»

Достаточно одного истинного условия. Как в жизни: либо то, либо другое, либо оба сразу.

NOT — «не»

Отрицание. Применяется к целому выражению, поэтому скобки — ваши лучшие друзья.

Приоритет: NOT > AND > OR . То есть A OR B AND C читается как A OR (B AND C) , а не как (A OR B) AND C . Это ровно та ошибка, из-за которой в отчёт попадают лишние строки: department_id = 4 OR department_id = 1 AND salary > 140000 не применяет порог к отделу 4. Ставьте скобки, даже когда кажется, что и так понятно.

Рабочий пример: AND, OR и скобки 

SELECT /* выбираем столбцы результата */ name
FROM /* указываем таблицу-источник */ Employee
WHERE /* фильтруем отдельные строки */ (department_id = 4 OR department_id = 1)
  AND salary > 140000;

Сначала выбираются сотрудники из отделов 4 или 1, затем для обоих отделов применяется порог зарплаты.

SELECT /* выбираем столбцы результата */ name

Результат: только Анна: она из отдела 1 или 4 и получает больше 140 000. Борис не проходит по зарплате, Ирина — по отделу.

Сложный вариант 7: Сложная логика с AND, OR и скобками

AND имеет более высокий приоритет, чем OR. Скобки помогают явно показать, какие условия должны выполняться вместе. 

SELECT /* выбираем подходящих сотрудников */ name, salary, department_id
FROM Employee
WHERE /* высокая зарплата в отделе 2 или роль руководителя */ (department_id = 2 AND salary >= 100000)
   OR (role = 'lead' AND status = 'active') /* оба условия для руководителя обязательны */;

На что обратить внимание: Комментарии внутри запроса объясняют назначение частей. Попробуй убрать комментарии и пересказать логику своими словами.

IN / NOT IN

IN — «входит в»

Сокращение для длинной цепочки OR . WHERE city IN (\'Москва\', \'Казань\') — то же самое, что city = 'Москва' OR city = 'Казань' , только короче и читаемее.

NOT IN — «не входит в»

Отрицание IN . Осторожно с NULL : если в списке или в столбце есть NULL , NOT IN может вернуть пустой результат.

Ловушка NOT IN : WHERE id NOT IN (1, 2, NULL) не вернёт ничего . Потому что id <> NULL даёт NULL , а не true , и всё выражение становится неопределённым. Если в подзапросе может быть NULL , используйте NOT EXISTS или добавьте WHERE col IS NOT NULL .

Рабочий пример: Проверка списка значений 

SELECT /* выбираем столбцы результата */ name
FROM /* указываем таблицу-источник */ Client
WHERE /* фильтруем отдельные строки */ city IN ('Москва', 'Казань');

Вернутся клиенты из Москвы или Казани. Для NOT IN проверяется, что значение не входит в список; учитывайте NULL.

Ирина Омск

WHERE /* фильтруем отдельные строки */ city IN ('Москва', 'Казань');

3. Что получится

Данные: Анна — Москва; Борис — Казань; Ирина — Омск.
Результат: Анна и Борис. Омск не входит в список в скобках.

Сложный вариант 8: Проверить несколько значений и исключения

IN сокращает длинную цепочку OR. Помни, что NULL в списке NOT IN может дать неожиданный результат; для таких задач часто лучше NOT EXISTS. 

SELECT /* выводим клиентов из нужных городов */ name, city
FROM Client
WHERE city IN ('Казань', 'Самара', 'Пермь') /* одно из перечисленных значений */
  AND city NOT IN ('Самара') /* дополнительно исключаем Самару */;

На что обратить внимание: Комментарии внутри запроса объясняют назначение частей. Попробуй убрать комментарии и пересказать логику своими словами.

BETWEEN

BETWEEN — «между»

Один шаг BETWEEN любовь AND ненависть.

Нюанс

BETWEEN a AND b включает оба конца: то же самое, что >= a AND <= b . Для чисел и дат работает одинаково. Для дат с временем будьте осторожны: BETWEEN '2024-01-01' AND '2024-01-31' не поймает записи за 31 января с временем 15:00 , потому что '2024-01-31' — это полночь. Надёжнее диапазон с < следующего дня.

Рабочий пример: Диапазон через BETWEEN 

SELECT /* выбираем столбцы результата */ product_name, price
FROM /* указываем таблицу-источник */ Product

LIKE / ILIKE и спецсимволы

LIKE — «как», «похож»

«I like to move it — move it...» Нет, это не лайк, ну, во всяком случае — не в том смысле, в котором вы могли бы подумать. 'Даша' LIKE 'Петя' не значит, что Даше нравится Петя. В данном случае это предлог «как» или причастие «похож», то бишь — разве что только количеством букв в имени. В языке SQL обзывается паттерном (шаблоном).

ILIKE — «похож, но без учёта регистра»

Расширение PostgreSQL. То же самое, что LIKE , но 'Moscow' ILIKE 'moscow' вернёт true . Незаменим, когда данные вводят люди, и «Москва», «москва» и «МОСКВА» — это одно и то же.

Нюанс

Как работает LIKE . Он сравнивает строку слева с шаблоном справа. Шаблон — это обычный текст, в котором два символа имеют особый смысл: % и _ . Всё остальное — литералы, то есть совпадает само с собой. Результат — true или false для каждой строки.

Символ Что означает Пример
% любое количество символов, включая ноль 'Иван%' — «Иван», «Иванов», «Иван Петров»
_ ровно один любой символ 'Иван_' — «Иваны», «Иван!», но не «Иван»

Шаблон Что найдёт

Уровень 3 — условная логика

CASE / WHEN / THEN / ELSE / END

CASE — «если..., то...»

CASE проверяет условия по порядку и возвращает результат первого совпавшего WHEN. ELSE срабатывает, если совпадений нет.

SELECT /* выбираем столбцы результата */ name,

            ELSE /* запасной вариант, если условия не сработали */ 'Начальная'

Сложный вариант 12: Сгруппировать сотрудников по диапазону зарплаты

      WHEN salary >= 80000 THEN 'Средняя'

    CASE WHEN salary >= 150000 THEN 'Высокая' WHEN salary >= 80000 THEN 'Средняя' ELSE 'Начальная' END;

HAVING

WHERE фильтрует исходные строки до группировки. HAVING фильтрует уже сформированные группы, например по COUNT(*) или AVG().

HAVING /* фильтруем уже сформированные группы */ COUNT(*) >= 5;

OVER и оконные функции

OVER

Оконная функция вычисляет показатель по связанным строкам, но не схлопывает их в одну строку на группу, как GROUP BY.

Рабочий пример: зарплата и средняя по отделу 

SELECT /* выбираем столбцы результата */ name, department_id, salary,
       AVG(salary) OVER (PARTITION BY department_id) AS dept_avg
FROM /* указываем таблицу-источник */ Employee;

Каждый сотрудник остаётся отдельной строкой, а рядом появляется средняя зарплата его отдела.

Сложный вариант 18: Сравнить зарплату со средней по отделу

GROUP BY сократил бы отдел до одной строки. Оконная функция рассчитывает статистику по группе, но оставляет отдельную строку каждого сотрудника.

    salary - AVG(salary) OVER (PARTITION BY department_id) AS diff_from_avg /* отклонение от среднего */
FROM Employee; /* оконная функция не схлопывает строки */

PRIMARY KEY / FOREIGN KEY

PRIMARY KEY

Первичный ключ однозначно идентифицирует строку и не допускает NULL или повторов. FOREIGN KEY связывает значение с ключом другой таблицы и помогает поддерживать целостность данных.

Рабочий пример: связь сотрудников с отделами 

/* Пояснение: ниже показан SQL-фрагмент для этого примера. */
CREATE TABLE Department (
  id INTEGER PRIMARY KEY,
  department_name VARCHAR(100) NOT NULL
);
CREATE TABLE Employee (
  id INTEGER PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  department_id INTEGER REFERENCES Department(id)
);

Каждый id отдела уникален. department_id сотрудника может ссылаться только на существующий Department.id (если значение не NULL).

Порядок выполнения запроса

Примеры, нюансы и дополнительная информация

Порядок написания SQL и логический порядок обработки — не одно и то же. Обычно запрос пишут с SELECT в начале, но логически обработка идёт примерно так:

1. FROM / JOIN — определить источники и соединить таблицы
2. WHERE — отфильтровать строки
3. GROUP BY — сформировать группы
4. HAVING — отфильтровать группы
5. SELECT — вычислить столбцы, выражения и CASE
6. DISTINCT — убрать дубликаты результата
7. ORDER BY — отсортировать итог
8. LIMIT / OFFSET — ограничить и пропустить строки

Полный рабочий пример

SELECT /* выбираем столбцы результата */ d.department_name AS department,
       COUNT(*) AS employee_count,
       AVG(e.salary) AS average_salary
FROM /* указываем таблицу-источник */ Employee AS e
JOIN /* соединяем таблицы */ Department AS d ON d.id = e.department_id
WHERE /* фильтруем отдельные строки */ e.salary >= 50000
GROUP BY /* объединяем строки в группы */ d.department_name
HAVING /* фильтруем уже сформированные группы */ COUNT(*) >= 2
ORDER BY /* сортируем результат */ average_salary DESC
LIMIT /* ограничиваем число строк */ 5;

Как читается: берём сотрудников и их отделы → оставляем зарплаты от 50 000 → группируем по отделам → оставляем отделы хотя бы с двумя сотрудниками → считаем количество и среднюю зарплату → сортируем по средней зарплате от большей к меньшей → показываем первые пять отделов.

AS задаёт понятные имена результирующих столбцов. В большинстве СУБД псевдоним из SELECT можно использовать в ORDER BY, но нельзя напрямую использовать в WHERE того же уровня.

Сложный вариант 25: Собрать отчёт с CTE, JOIN и HAVING

CTE (WITH) даёт имя промежуточному набору данных. Далее JOIN связывает его с отделами, GROUP BY собирает статистику, HAVING фильтрует группы. 

WITH active_employees AS ( /* сначала готовим набор активных сотрудников */
    SELECT id, name, department_id, salary
    FROM Employee
    WHERE status = 'active'
)
SELECT /* строим сводный отчёт по отделам */
    d.department_name,
    COUNT(a.id) AS employee_count,
    ROUND(AVG(a.salary), 2) AS avg_salary
FROM Department AS d
JOIN active_employees AS a ON a.department_id = d.id /* связываем сотрудников с отделами */
GROUP BY d.id, d.department_name
HAVING COUNT(a.id) >= 2 /* оставляем отделы минимум с двумя активными сотрудниками */
ORDER BY avg_salary DESC; /* сначала отделы с большей средней зарплатой */

На что обратить внимание: Комментарии внутри запроса объясняют назначение частей. Попробуй убрать комментарии и пересказать логику своими словами.
